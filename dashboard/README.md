# Fixed Income Engineering Dashboard

A dark local web UI for this repository. Financial figures are generated by `fixed_income_dashboard_data`, which links to the same C++ `fixed_income` library used by the demo. The browser does not reimplement bond pricing.

## Build and run

From the repository root:

```bash
cmake -S . -B build
cmake --build build --parallel 2
python3 dashboard/server.py
```

Open <http://127.0.0.1:8080>.

The dashboard binds to loopback by default. Keep it local unless you add proper authentication and deployment hardening.

## Financial analytics

- Notional, coupon and YTM inputs are passed to the C++ executable.
- The executable returns price, duration, convexity, DV01/PV01, a price/yield series, and rate-shock scenarios.
- Dates and coupon frequency are currently fixed demo assumptions in `src/dashboard_data.cpp`; input values are not live market quotes.
- Values reflect the current implementation of the C++ library. They should not be treated as validated market valuations until the outstanding date/day-count and financial-convention issues are addressed.

## SonarQube integration

Set these environment variables in the server process:

```bash
export SONAR_HOST_URL="https://your-sonarqube.example"
export SONAR_PROJECT_KEY="your-project-key"
export SONAR_TOKEN="your-token"
python3 dashboard/server.py
```

Use a least-privilege token. The token is read only by the server and is never sent to browser JavaScript. When configuration is absent, the UI shows `Not analyzed / not configured`; it does not invent zero-valued metrics. The API currently requests bugs, vulnerabilities, code smells, coverage, duplicated-lines density, lines of code, and security hotspots, plus the project quality gate.

For meaningful C++ coverage, configure the SonarQube C++ analyzer and provide a real coverage report from your test build. Merely connecting the measures API does not create coverage data or perform a scan.
